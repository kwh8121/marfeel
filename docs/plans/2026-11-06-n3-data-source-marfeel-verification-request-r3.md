## 0. 요청 요약

발제 문서 N3(독자 연결)의 세그먼트 가설을 어떤 출처로 검증할지 정한다. 제안은 **"N3 검증은 GA4 단독으로 한다. Marfeel은 N3에서 빼고 N4(시의성)와 유입 경로 분석을 맡는다"**이다.

r2에서 "보내기 전 확인"으로 남긴 GA4 전제 3개 중 2개(P1, P3)를 확인했다(0.1절). 결과는 이렇다.

- A·C 근사는 성립한다. 따라서 r2의 Q1(Marfeel로 A·C를 나눌 수 있나)은 결정 질문이 아니므로 뺐다.
- 대신 **봇으로 보이는 대량 트래픽**을 새로 찾았다(3.1절). 이 트래픽은 B 세그먼트(해외)의 비중을 부풀린다. 이를 Marfeel로 대조하는 QA가 이번 요청의 **필수 질문**이다.
- QB·QC는 GA4 Data API 확인(P2)이 실패할 때만 필요하다. P2 결과를 기다리지 않도록 미리 묻는다.

| 질문 | 성격 | 호출 상한 |
| --- | --- | --- |
| QA. 봇 의심 트래픽 대조 | **필수** | 3회 |
| QB. 72시간 기사별 조회 가능성 | 조건부 (P2 실패 시 GA4 대체용) | 2회 |
| QC. 보존 기간 | 조건부 (P2 실패 시 GA4 대체용) | 2회 |
| 합계 | | **7회 이하** |

**범위 밖:**

- 게이트 2(발행 기사 반응)의 출처와 결과 변수는 별도 결정(D2)으로 다룬다. 질문은 별도 요청서로 보낸다.
- N3 판정 설계(통계)는 부록 A에 기록만 한다. 검증 대상이 아니며 의견은 받는다.

### 0.1 GA4 선행 확인 결과 (속성 `0. GA4_코리아타임스_통합` 340662437)

| # | 항목 | 결과 | 판정 |
| --- | --- | --- | --- |
| P1 | 국내 사용자의 `languageCode` 분포 (2026-10-09~11-05, 28일) | 국내 활성 사용자 240,619명. `ko-kr` 54.9%, `ko` 5.6%로 한국어는 약 60.5%. 비한국어는 약 39.5%로 `en-us` 27.5%, `en-gb` 5.7%, 그 외 영어권·독일어·중국어·프랑스어가 각 1% 미만 | **통과.** 사전 경계 5~95% 안이다. 비중은 행 합 기준이며, 한 사용자가 여러 언어 행에 잡히면 중복될 수 있다(추정) |
| P2 | Data API `runReport` 72시간 조회의 샘플링·임곗값 | 미측정. 응답 `metadata.subjectToThresholding`, `metadata.samplingMetadatas`로 확인할 예정 | **대기** |
| P3 | Google 신호, 보고 ID | Google 신호는 **켜짐**. 관리 화면에 "Google 신호 데이터는 Google 애널리틱스 보고 ID에 포함되지 않는다"고 표시된다. 보고 ID는 **혼합됨**. 국가 × 언어 코드 보고서는 "사용 가능한 데이터 100%"로 나오고 임곗값 표시는 없었다 | **문제없음 (UI 기준).** API 기준은 P2로 확인한다. 설정은 바꾸지 않았다 |

P1의 한계: `en-us`가 국내 사용자의 27.5%다. 이 안에 영어 설정을 쓰는 한국인이 얼마나 섞였는지는 알 수 없다. A 근사가 실제로 A를 가리키는지(타당도)는 검증하지 못한 채로 진행한다.

## 1. 배경

N3 가설: 같은 수치라도 독자 집단마다 관심 각도가 다르다. 세그먼트는 아래 3개이며, KT 독자 구성을 확인하지 않은 추측이다.

| 세그먼트 | 정의 | 가설상 관심사 |
| --- | --- | --- |
| A | 국내 거주 외국인 (근로자·유학생·주재원) | 생활비, 월세, 비자·체류 정책 |
| B | 해외 Korea watcher (투자자·학계·정책) | 거시, 반도체 수출, 출산율, 금리 |
| C | 국내 영어 독자 | 국문 매체와 같은 관심사 |

- 검증 대상은 **각도 유형(5개) × 세그먼트의 상호작용**이다. 각도 유형은 헤드라인 수치, 품목 롱테일, 국제 비교, 외국인 관련, 정책 연결이다.
- 세그먼트는 방문자 속성(국가, 언어)으로만 정의한다. 기사 주제로 정의하는 것은 순환 판정이므로 금지한다.
- 판정 결과의 쓰임
  - 갈리면: N3을 세그먼트 태깅으로 유지한다.
  - 갈리지 않으면: N3을 단일 "독자 연결 점수"로 축소한다.
  - 표본 부족이면: "판정 보류"로 둔다. 갈리지 않음으로 처리하지 않는다.

### 2.2 세그먼트 근사 정의 (GA4)

| 세그먼트 | 조건 | 남는 한계 |

### 2.3 봇 의심 트래픽 제외 규칙 (r2의 "이상 국가 제외"를 대체)

**r2 규칙을 버린 이유:**

- 비교할 직전 기간이 없다. 백테스트 기간과 같은 길이의 직전 기간은 2022-11부터인데, GA4 데이터는 2023-03부터다.
- 28일 급증이 24개월 평균에 묻힌다.
- 국가를 통째로 빼면 실제 독자까지 빠진다.
- 참여율 기준이 작동하지 않는다. 아래 사례가 그렇다.

**근거 사례 (2026-10-09~11-05):**

| 행 (국가 × 언어) | 활성 사용자 | 신규 비율 | 참여율 | 사용자당 세션 | 사용자당 평균 참여 시간 |
| --- | --- | --- | --- | --- | --- |
| Singapore × `en-us` | 283,445 (속성 전체의 약 10%) | 98.7% | 93.67% | 1.00 | **4초** |
| Singapore × `en-gb` | 34,283 | 81.3% | 88.23% | 1.25 | 1분 01초 |
| Singapore × `en-sg` | 27,671 | 90.5% | 81.69% | 1.09 | 43초 |
| South Korea × `ko-kr` | 132,099 | 94.9% | 89.8% | 1.31 | 2분 47초 |

- 참여 시간이 4초인데 참여율이 94%다. 그래서 이 속성에서는 참여율과 참여 세션으로 봇을 거를 수 없다. 주요 이벤트가 거의 모든 세션에서 발생하도록 설정된 것으로 보인다(추정).
- 싱가포르 전체를 빼면 `en-gb`·`en-sg` 행의 독자도 빠진다. 이 행들은 참여 시간이 43초~1분으로 정상 범위로 보인다.

**새 규칙 (기준값은 근거 없는 제안값):**

- 단위: 월 × 국가 × `languageCode` 행
- 제외 조건: 아래 3개를 모두 만족하는 행
  - 사용자당 평균 참여 시간 10초 미만
  - 신규 사용자 비율 95% 이상
  - 사용자당 세션 1.05 이하
- 규칙은 백테스트 전에 고정한다. 제외 목록은 월별로 기계적으로 산출해 기록한다. 기사별로 바꾸지 않는다.
- 결과 변수는 제외 행을 뺀 활성 사용자다. 참여 세션은 쓰지 않는다(위 사례).
- 민감도 분석: 제외 전과 제외 후로 각각 판정하고, 결론이 바뀌는지 보고한다.
- 대조: 같은 기간 Marfeel의 싱가포르 비중과 체류 지표를 본다(QA).

## 4. 검증 질문

각 질문에 결론(예/아니오/부분), 근거(API 문서 링크, 실측 요청·응답 요약), 실측 여부를 표시해 달라. 추측은 추측이라고 표시한다.

### QA. 봇 의심 트래픽 대조 (필수, 호출 3회 이하)

**QA.1** 2026-10-09~11-05 동안 Marfeel에서 싱가포르의 PV 비중(전체 대비)과 체류 지표는 얼마인가? 같은 기간 한국과 미국 값도 같이 달라.

- GA4 기준 싱가포르는 활성 사용자의 12.2%이고, 그중 `en-us` 행은 평균 참여 시간이 4초다.
- 판단 기준:
  - Marfeel 비중이 GA4보다 뚜렷이 낮으면(예: 절반 이하), Marfeel이 이 트래픽을 걸렀거나 수집하지 않은 것이다. 2.3 제외 규칙을 지지하는 근거다.
  - 비슷하면 실제 트래픽일 가능성을 다시 검토한다.

**QA.2** 같은 대조를 브라질·아르헨티나에도 해 달라. GA4 기준 28일 증가율은 각각 +144%, +169%다.

**QA.3** Marfeel의 봇·비정상 트래픽 필터 정책은 무엇인가? 공개 문서에 있는 만큼 답하고, 나머지는 "담당자 확인 필요"로 표시한다. **[담당자]** (호출 0회)

**QA.4** 2026-10-22 실측의 "해외 약 2/3"에 싱가포르가 얼마나 들어 있었는지, 그날 데이터를 다시 조회할 수 있는가? 할 수 있으면 QA.1 호출 안에서 처리한다. 추가 호출은 하지 않는다.

### QB. 72시간 기사별 조회 가능성 (조건부, 호출 2회 이하)

P2에서 GA4 Data API 응답에 임곗값·샘플링이 대량으로 걸릴 경우, Marfeel이 N3 백테스트를 대신할 수 있는지 판단하기 위한 질문이다.

1. 한 번의 호출로 "기사 N건 × 각자 발행 후 72시간 × 국내·해외 2분할"을 받을 수 있는가? 안 되면 기사 100건 기준 최소 호출 수와 소요 시간(분당 1회, 공유 경합 포함)은 얼마인가?
2. `url`(또는 동등한) 필터에 여러 URL을 넣을 수 있는가? 상한은 몇 개인가? 필터가 조용히 무시되지 않았는지는 합계 변화로 확인한다(데이터 범위 8절).
3. Marfeel은 URL 개편 전후 경로(`/pages/article.asp/{ID}`와 신규 슬러그 경로)를 같은 기사로 묶는 안정적인 키를 주는가?

### QC. 보존 기간 (조건부, 호출 2회 이하)

1. 기사별·국가별 데이터는 몇 개월 보존되는가? 2024-11 이전 기사의 72시간 데이터를 지금 조회할 수 있는가? **[담당자]**
2. 보존 기간이 2025-04(URL 개편)보다 짧으면, QB.3은 답할 필요가 없다고 표시해 달라.

### QD. 제안 전체에 대한 반론 (호출 0회)

1. "N3은 GA4 단독, Marfeel은 N4·유입 경로 전담"보다 나은 배분이 있는가?
2. Marfeel `source`(Discover·검색·소셜)를 기사 단위 통제 변수로 넣어야 하는가? 예를 들어 Discover 비중이 높은 기사는 해외 비중이 높게 나오는 식의 교란이 있을 수 있다. 결과 변수를 섞는 것이 아니라 공변량으로만 쓰는 경우다.

## 5. 회신 형식

- 질문별 표: 질문 번호 | 결론 | 근거 | 실측 여부 | 사용한 호출 수
- 실측했다면 요청 파라미터와 응답 요약을 붙이고, 시각(KST)과 429 발생 여부를 적는다.
- **[담당자]** 질문 중 확인하지 못한 것은 담당자에게 물을 질문 문장으로 따로 적는다.
- 제안을 바꿔야 한다면, 바꿀 부분을 2.1 표 형식으로 다시 적는다.

## 6. 제약

- 전체 실측 호출은 **7회 이하**로 한다. 호출 사이 간격은 65초 이상 둔다. QA를 먼저 한다.
- 09:05~09:49 KST는 피한다. 경합은 하루만 관측했으므로 규칙성은 모른다.
- 429가 나면 "보류"로 기록한다. 0으로 기록하지 않는다. 같은 질문의 재시도는 1회까지만 한다.
- 결과 변수는 한 비교 안에서 Marfeel과 GA4 수치를 섞지 않는다. QA는 대조용이며 결과 변수가 아니다.
- 편집국 합의가 필요한 값(예: 게이트 2 목표 상대 PV 1.2배)은 변경 제안만 하고 확정하지 않는다.

## 부록 A. N3 판정 설계 (요청자 내부용 · 검증 대상 아님 · 의견 환영)

모든 수치 기준은 근거 없는 제안값이다.

**A1. 사전 점검 (API 호출 0회).** CMS 대상 기사 목록에 각도 유형 라벨을 붙여 유형별 기사 수를 센다. 15건 미만인 유형은 처음부터 "표본 부족"으로 두고 판정 범위에서 뺀다.

**A2. 결과 변수**

- 구성: 세그먼트 비중 리프트 = 각도 유형의 세그먼트 비중 ÷ 통계 기사 전체의 세그먼트 비중
- 규모: 상대 사용자 수 = 기사 72시간 활성 사용자 ÷ 직전 90일 발행 통계 기사의 72시간 활성 사용자 중앙값
- 단위: 2.3 제외 행을 뺀 활성 사용자. AMP·슬러그 분리 행은 CMS 기사 ID로 합친다.
- 리프트는 높은데 규모가 낮은 칸은 "소수 집단에 치우쳤지만 읽히지 않음"으로 따로 표시한다.

**A3. 최소 표본.** 칸(각도 유형 × 세그먼트)마다 기사 15건 이상, 세그먼트 사용자 합계 300명 이상이어야 한다.

**A4. 단계적 판정**

1. 1단계, 국내 vs 해외(5칸)
2. 2단계, A vs C(5칸). 1단계에서 판정이 나고 최소 표본을 채운 칸만 판정한다.
   - 사전 예상: A 근사는 기사당 약 10명이다(국내 약 1/3 × 비한국어 약 40% × 72시간 사용자 약 75명, 추정). 칸당 300명이면 기사 약 30건이 필요하다. 표본이 100건 안팎이면 **2단계 대부분 칸은 보류될 것으로 예상한다.** 보류는 실패가 아니다.

**A5. 다중비교와 검정력**

- 단계마다 기사 단위 부트스트랩으로 99% 구간을 구한다(5칸 본페로니 근사).
- 구간 전체가 1.2 이상이거나 0.8 이하인 칸이 1개 이상이면 그 단계에서 "갈린다"로 본다.
- 시험 조회(기사 20건)로 예상 구간 폭을 추정한다. 폭이 0.4를 넘으면 판정 보류로 두고 표본 확대를 먼저 검토한다. 폭 0.4일 때 검출 가능한 최소 리프트는 약 1.4다.
- 경계 1.2 / 0.8은 게이트 2의 "상대 PV 1.2배"와 무관하다.

**A6. 기사 키.** 개편 전 `/pages/article.asp/{ID}`, 개편 후 슬러그 경로, 슬러그 수정으로 갈라진 행, AMP 경로(100자 절단 → CMS 슬러그 앞부분과 맞춤)를 CMS 기사 ID 하나로 묶는다. 맞지 않아 버린 행의 비율을 기록한다. CMS에서 기사 ID, 발행 시각, 슬러그 이력을 받는 것이 전제이며, 담당자는 확인이 필요하다.
