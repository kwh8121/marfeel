## 4. 2단계 쓰기 상세 (S7)

### 4.1 초안 저장 (`herb_write`)

1.  api가 `PUT /v1/drafts/{key}`에서 `status=final`을 기록하는 **같은 트랜잭션 안에서** `jobs`에 `herb_write` 등록(`dedupe_key = draft:{id}`, max_attempts 3) [DB 설계 v1 §4.5].
    
2.  작업 payload에는 `draft_id`만 넣는다. 실행 시점에 `drafts.final_text`를 읽는다.
    
3.  jobs 레인이 Mock `POST /api/article` 호출: `external_id = draft_id`(항상 전송), draft 상태 고정, `ai_generated = true`.
    
4.  성공 시 `drafts.herb_article_id` 저장. 이미 값이 있으면 호출하지 않고 끝낸다(재실행 방어).
    
5.  오류 처리 [결정 D1]:
    

| 분류 | 해당 오류 | 처리 | 이유 |
| --- | --- | --- | --- |
| 자동 재시도 | 연결 거부·DNS 실패(요청이 서버에 닿지 않음), 429, 503 | 백오프 재시도, 최대 3회 | 서버가 요청을 처리하지 않은 것이 확실하다 |
| 재시도 안 함 | 400, 401(토큰 갱신 1회 후에도 실패), 403, 409 | 즉시 `failed`, 오류 코드 기록, 알림 1건 | 다시 보내도 결과가 같다 |
| 결과 불명 | 응답 시간초과, 응답 도중 연결 끊김, 500·502·504 | 자동 재시도 안 함. `failed` + 오류 `unknown_result` 기록, 알림 1건 | 서버가 이미 기사를 만들었을 수 있다. `external_id` 중복 방지가 실제 Herb에서 확인되기 전에는 재전송하면 기사가 두 번 생길 수 있다 |

6.  `결과 불명` 관리자 처리 절차: 관리자가 Herb에서 해당 초안 존재 여부를 확인한 뒤 ① 있으면 `herb_article_id`를 수동 기록 ② 없으면 실패 작업 재처리. 화면 정의서 r3의 실패 작업 목록(예: j-30211)에 재처리 동작과 `herb_article_id` 수동 기록 입력이 없으면 추가한다(§4.6).
    
7.  실제 Herb가 `external_id` 중복 방지를 지원한다고 확인되면 `결과 불명` 분류를 `자동 재시도`로 옮긴다. 분류표 설정만 바꾸며 코드 경로는 그대로다.
    

### 4.2 정정 경고 메모 (`herb_memo`)

1.  정정·취소가 확정되고(r8 §5.5⑤-3) 해당 사안에 초안이 있으면 `herb_memo` 등록(`dedupe_key = memo:{change_event_id}:{draft_id}`).
    
2.  `herb_article_id`가 아직 없으면(쓰기 대기·재시도 중) 메모 작업은 실패로 끝내지 않고 `run_after`를 늦춰 다시 기다린다. `herb_write`가 최종 실패하면 메모도 실패 처리하고 알림 1건으로 묶는다.
    
3.  메모 호출 오류도 §4.1 분류표를 그대로 쓴다. 메모는 중복돼도 피해가 작지만, 규칙을 하나로 유지하기 위해 같은 표를 적용한다.
    
4.  Mock `POST /api/articlememo`는 자기 생성 기사만 허용한다.
    

### 4.3 데이터 변환 (순수 함수, `domain/`)

**(1) 초안 출력 형식 [결정 D3]**
체인(`translate`·`rewrite`·`style_only`) 마지막 단계의 출력은 아래 형식으로 고정한다.

```
HEADLINE: <제목 한 줄>
SUBHEADLINE: <부제 한 줄, 없으면 줄 생략>
BODY:
<본문. 문단은 빈 줄로 구분>
```

*   파서(`domain/draft_format.py`)는 순수 함수로 만들고, `HEADLINE:`·`BODY:` 블록이 모두 있어야 성공으로 본다.
    
*   파싱 실패 시 대체 규칙: headline = 사안 대표 제목, subheadline 없음, body = 전체 출력. 이때 `drafts.step_outputs`에 `format_fallback = true`를 기록하고 G 지표 집계(초안 형식 준수율)에 포함한다. 저장은 막지 않는다.
    
*   이 형식은 OWU Workspace 모델 프롬프트에 넣는다(T5에서 반영).
    

**(2) 본문 HTML 변환 [결정 D2]**

*   허용 태그는 설정 `HERB_BODY_ALLOWED_TAGS`(기본 `p`)로 둔다.
    
*   변환 규칙: 빈 줄로 나뉜 문단마다 `<p>…</p>`로 감싸고, 그 밖의 `<`·`>`·`&`는 모두 이스케이프한다. 모델이 출력한 HTML·Markdown 태그는 그대로 통과시키지 않는다.
    
*   Herb가 허용 태그를 알려 오면 설정값만 바꾼다.
    

**(3) 섹션·담당자 [결정 D2]**

*   `HERB_WRITE_SECTION`·`HERB_WRITE_ASSIGNEE`가 설정돼 있을 때만 요청에 넣는다. 기본은 미설정.
    
*   Herb가 필수라고 회신하면 설정값을 채운다. 기자별 담당자 매핑이 필요하다고 회신하면 그때 별도 작업으로 추가한다(지금은 만들지 않음).
    

### 4.4 사용자에게 보이는 결과 [결정 D4]

*   Pipe 최종 출력 끝에 1줄을 붙인다: `Herb 초안 저장을 요청했습니다. 결과는 '기사' 명령에서 확인하세요.`
    
*   `기사` 추적에 "Herb 저장" 상태 칸을 둔다. 상태는 저장하지 않고 계산한다.
    

| 표시 | 계산 조건 |
| --- | --- |
| 대기 | `herb_write` 작업이 `queued`·`running` |
| 완료 (articleId) | `drafts.herb_article_id` 값 있음 |
| 실패 (사유) | 작업 `failed`, 오류가 `unknown_result`가 아님 |
| 결과 불명 — 관리자 확인 중 | 작업 `failed`, 오류 `unknown_result` |

*   실패·결과 불명은 기존 `notices` + `outbox` 웹훅으로 관리자에게 1건 알린다(r8 §5.5⑤의 알림 경로 재사용). 기자에게 따로 푸시 알림을 보내지 않는다.
    

### 4.5 완료 기준

*   같은 `draft_id`로 `final`을 3회 기록하고 작업을 2회 강제 재실행해도 Mock 기사 1건, `herb_article_id` 1개

*   `기사` 추적의 "Herb 저장" 4개 상태가 계산 조건대로 표시 [D4]
