# N3 세그먼트 검증 데이터 출처 결정 — Marfeel API 검증 요청

- 작성: 2026-11-06 · 요청자: Kwak won-hee (KT AI 엔지니어링)
- 받는 쪽: Marfeel API 전문 에이전트
- 관련 문서: 「데이터 기반 발제 에이전트 — 관심을 끄는 발제의 필요·충분조건」(이하 "발제 문서"), 「발제 에이전트 문서의 GA→Marfeel 대체 평가」(이하 "대체 평가"), `references/marfeel-data-scope.md`(이하 "데이터 범위")

## 0. 요청 요약

발제 문서의 N3(독자 연결) 세그먼트 가설을 어떤 출처로 검증할지 결정하려 한다. 현재 제안은 **"N3 검증은 GA4 단독, Marfeel은 N3에서 빼고 N4(시의성)와 유입 경로 분석 전담"**이다.

이 제안이 Marfeel의 실제 능력을 과소평가했는지 검증해 달라. 특히 아래 두 가지가 틀렸다면 제안은 뒤집힌다.

1. Marfeel로는 국내 독자를 A(국내 거주 외국인)와 C(국내 영어 독자)로 나눌 방법이 없다.
2. Marfeel로는 기사 약 100건 × 발행 후 72시간 × 국가 분리 조회를 현실적인 시간 안에 할 수 없다.

## 1. 배경

### 1.1 N3이 검증하려는 것

같은 수치라도 독자 집단마다 관심 각도가 다르다는 가설이다. 세그먼트는 아래 3개이며, KT 독자 구성을 확인하지 않은 추측이다.

| 세그먼트 | 정의 | 가설상 관심사 |
| --- | --- | --- |
| A | 국내 거주 외국인 (근로자·유학생·주재원) | 생활비, 월세, 비자·체류 정책 |
| B | 해외 Korea watcher (투자자·학계·정책) | 거시, 반도체 수출, 출산율, 금리 |
| C | 국내 영어 독자 | 국문 매체와 같은 관심사 |

통계적으로는 **각도 유형(5개) × 세그먼트의 상호작용(interaction)** 검증이다. 각도 유형은 헤드라인 수치, 품목 롱테일, 국제 비교, 외국인 관련, 정책 연결이다.

원칙:

- 세그먼트는 방문자 속성(국가, 언어 등)으로만 정의한다.
- 기사 주제나 섹션으로 세그먼트를 정의하면 순환 판정이 되므로 금지한다.

### 1.2 판정 결과가 바꾸는 것

- **각도 선호가 세그먼트별로 갈리면**: N3을 세그먼트 태깅으로 유지한다.
- **갈리지 않으면**: 세그먼트 표를 삭제하고, N3을 단일 "독자 연결 점수"로 축소한다.

## 2. 현재 제안 (검증 대상)

### 2.1 출처 배분

| 필요조건·용도 | 출처 | 근거 |
| --- | --- | --- |
| N3 백테스트 (과거 24개월) | GA4 | 세그먼트 3개 근사 가능, 이력 확인됨, 72시간 조회 시 샘플링 없음 |
| 게이트 2 (발행 기사 72시간 반응) | GA4 | 백테스트와 같은 결과변수를 써야 가중치를 그대로 적용할 수 있음 |
| N4 시의성 | Marfeel | `searchImpressions`, 실시간 급상승 |
| 유입 경로 라벨 (R6) | Marfeel | GA4는 Direct + Unassigned가 약 66% |
| GA4 국가 비중의 봇 왜곡 대조 | Marfeel (1회, 선택) | 결과변수로는 쓰지 않음 |

### 2.2 세그먼트 근사 정의 (GA4)

| 세그먼트 | 조건 | 남는 한계 |
| --- | --- | --- |
| A 근사 | `country` = South Korea, `languageCode` ≠ ko | 영어 브라우저를 쓰는 한국인이 섞임 |
| C 근사 | `country` = South Korea, `languageCode` = ko | 한국어 브라우저를 쓰는 외국인이 섞임 |
| B 근사 | `country` ≠ South Korea, 이상 국가 제외 | K-culture 독자가 섞임 |

### 2.3 지표와 판정 규칙

- 지표는 세그먼트별 PV가 아니라 **세그먼트 비중 리프트(lift)**다.
  - 리프트 = 각도 유형의 세그먼트 비중 ÷ 통계 기사 전체의 세그먼트 비중
  - 측정 단위는 활성 사용자 또는 참여 세션이다. PV는 쓰지 않는다.
- 판정: 기사 단위 부트스트랩으로 95% 구간을 구한다.
  - 구간이 1.2 이상이거나 0.8 이하에 들어가는 칸이 2개 이상이면 "갈린다"로 본다.
  - 이 기준값은 제안값이며 근거는 없다.

## 4. 검증 질문

각 질문에 **결론(예/아니오/부분)**, **근거**(API 문서 링크, 실측 요청·응답 요약), **실측 여부**를 표시해 달라. 추측은 추측이라고 표시한다.

### Q1. A·C 분리 (제안을 뒤집을 수 있는 핵심 질문)

1. Marfeel에 방문자 언어, 브라우저 언어, `Accept-Language` 계열 차원이 있는가? 문서에 없어도 원시 이벤트, 커스텀 차원, 내보내기(export)로 얻을 수 있는가?
2. 도시·지역(`city`, `region`) 차원이 있는가? 외국인 밀집 지역으로 A를 근사하는 방법이 의미 있는지도 의견을 달라.
3. 위 방법 외에 국내 독자를 방문자 속성으로 나눌 수 있는 차원이 있는가? 기사 주제로 나누는 방법은 제외한다.

### Q2. 72시간 고정 기간 기사별 조회

1. 한 번의 호출로 "기사 N건 × 각자 발행 후 72시간 × 국가 2분할"을 받을 수 있는가? 안 되면 최소 호출 수는 몇 회인가?
2. `url`(또는 동등한) 필터에 여러 URL을 넣을 수 있는가? 상한은 몇 개인가?
3. 기사 100건 × 국내·해외 = 약 200회라는 추정이 맞는가? 분당 1회와 공유 한도 경합을 감안한 실제 소요 시간은 얼마인가?
4. Marfeel은 URL 개편 전후 경로(`/pages/article.asp/{ID}`와 신규 슬러그 경로)를 같은 기사로 묶는가? 기사 ID 같은 안정적인 키를 주는가?

### Q3. 이력

1. 기사별·국가별 데이터는 며칠·몇 개월 보존되는가? 2024-11 이전 기사의 72시간 데이터를 지금 조회할 수 있는가?
2. 보존 기간이 24개월 미만이면, 확보 가능한 기간 안의 대상 통계 기사는 몇 건으로 추정되는가?

### Q4. 결과변수의 질

1. Marfeel의 봇·비정상 트래픽 필터 정책은 무엇인가? GA4에서 보이는 싱가포르·브라질·아르헨티나 급증이 Marfeel에도 같은 폭으로 보이는가?
2. 사용자 수(unique) 지표를 기사 × 국가 단위로 받을 수 있는가? PV만 되는가?
3. 응답에 샘플링이나 근사 집계가 있는가?

### Q5. 제안 전체에 대한 반론

1. "N3은 GA4 단독, Marfeel은 N4·유입 경로 전담"보다 나은 배분이 있는가? 있다면 이유를 달라.
2. 게이트 2를 GA4로 옮기면 잃는 것이 무엇인가? 실시간성, 발행 직후 판단 같은 것들이다.
3. Marfeel의 `source`(Discover·검색·소셜)를 세그먼트가 아닌 통제 변수로 넣어야 하는가? 예를 들어 Discover 유입 비중이 높은 기사는 해외 비중이 높게 나오는 식의 교란(confounding)이 있을 수 있다.

## 5. 회신 형식

- 질문별 표: 질문 번호 | 결론 | 근거 | 실측 여부
- 실측했다면 요청 파라미터와 응답 요약을 붙이고, 시각(KST)과 429 발생 여부도 적는다.
- 제안을 바꿔야 한다면, 바꿀 부분을 2.1 표 형식으로 다시 적는다.

## 6. 제약

- 호출 한도는 다른 주체와 공유한다. 실측은 경합이 적은 시간대에 하고, 429가 나면 "보류"로 기록한다. 0으로 기록하지 않는다.
- 결과변수(PV·사용자·체류)는 한 비교 안에서 Marfeel과 GA4 수치를 섞지 않는다.
- 편집국 합의가 필요한 값은 변경 제안만 하고 확정하지 않는다. 예: 게이트 2 목표인 상대 PV 1.2배.
