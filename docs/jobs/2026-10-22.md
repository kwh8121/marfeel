## Marfeel Reporting API 수집 가능 데이터 범위 파악

- 작업·브랜치·커밋: 로컬 조사 작업 · `main` · 커밋 없음
- 결과: `.env`의 API 전용 계정으로 인증·조회를 확인하고 이 계정(Korea Times, site 9291)에서 쓸 수 있는 지표·차원을 정리했다. 정리 문서는 [수집 가능 데이터 범위](../references/marfeel-data-scope.md). 진행은 10-21부터 이어졌다.
  - 앱 카탈로그 지표 27개를 추가 검증(전부 HTTP 200): 15개는 값 있음(`pageViewsPerArticle`, `uniqueUsersPerArticle`, `pageViewsPerUser`, 체류·참여·스크롤·`cumulativeRFV`, `searchCTR`, `discoverCTR`, `googleNews*`), 12개는 이름만 유효하고 0(`RPM`, `ARPU`, `revenueTotalPerArticle`, `googleNewsPosition`, `discoverMonitoring::*`, `socialMonitoring::*`). 값이 있는 지표는 총 28개
  - 처음 확인한 사용 가능 지표 13개: `uniqueUsers`, `pageViewsTotal`, `newArticles`, `discoverClicks`, `discoverImpressions`, `searchPosition`, `adsPerPage`, `socialPosts`, `totalDuration`, `averageRFV`, `adsImpressions`, `searchImpressions`, `searchClicks`
  - 이름은 유효하나 값이 0인 지표: `revenueTotal`, `CPM`, affiliation 4종, `productViews`, `totalItemsPurchased`
  - 확인된 차원 17개: `url`, `title`, `section`, `visitorFrequency`, `folder`, `host`, `uri`, `pageTechnology`, `country`, `sentiment`, `source`, `customerLoyalty`, `deviceType`, `medium`, `author`, `contentByAge`, `publishDate`
  - 요금제 제한(Enterprise, API `rawData` 403): `uniqueSessions`, `pageViewsPerSession`, `sessionsPerUser`, `uniqueRegisteredUsers`, `city`
- 수집 쿼리 3종 작성: [marfeel-queries](../references/marfeel-queries/README.md)(편집 성과·유입·Google). 세 파일 모두 실제 호출로 HTTP 200과 전 지표 반환 확인
- 수집 스크립트 작성: `scripts/marfeel_collect.py`(토큰 발급·캐시, 분당 1회 한도 준수, 401/429 재시도, JSON·CSV 저장). 사용법은 [수집 스크립트 가이드](../guides/marfeel-collection.md). `.gitignore`에 `data/` 추가
- 발견: 지표는 잘못된 이름이 조용히 무시된다(204/부분 응답). `groupBy`는 잘못된 이름도 200으로 받고 값이 앞 칸으로 밀려 라벨이 어긋난다. API 필드명은 화면 이름의 단순 camelCase 변환이 아니며 Marfeel Explore의 "Get JSON API"로만 확인된다(`deviceType`, `medium`, `adsImpressions` 등). Search 지표는 `medium`과 함께 쓰면 0이고 `deviceType`과는 값이 나온다.
- 검증: 로그인 200, 지표·차원별 조회 200 확인. 호출 한도 분당 1회를 지키며 수행했고 429는 1회 발생해 대기 후 해결. 비밀값(이메일·비밀번호·토큰)은 문서·일지에 기록하지 않음. 토큰은 스크래치패드에만 저장
- 미해결:
  - `revenueTotal`·`CPM`이 0인 원인(광고 수익 미연동 여부)은 운영 측 확인 필요. `hasRevenue` 플래그는 1
  - 사전의 나머지 후보(브라우저·OS, Recirculation, Page Speed, Conversions 등)의 실제 API 이름은 Explore에서 확인하지 못함
  - Search 지표와 `medium` 외 방문자 차원(`country`, `source` 등)의 조합 동작 미확인
  - 과거 데이터 보존 기간·날짜 경계·시간대 처리는 문서에 없음
- 다음 행동: 필요한 지표가 정해지면 Explore에서 해당 쿼리의 JSON을 받아 이름을 검증하고 수집 쿼리를 목적별(1~2 차원)로 나눠 설계. Enterprise 항목이 필요하면 요금제 업그레이드 검토
- 관련 링크: [수집 가능 데이터 범위](../references/marfeel-data-scope.md) · [Marfeel API 레퍼런스](../references/Marfeel%20API-reference.md)
